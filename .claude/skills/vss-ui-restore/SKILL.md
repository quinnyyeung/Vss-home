# VSS 首页还原规范

这个项目是把"小象超市供应商服务系统 VSS"后台首页的设计稿，用 React + Vite + Tailwind CSS 还原成一个可点击的演示 Demo。使用者前端基础较弱，所以代码要写得直白、注释要清楚。

Day 1 已经把整体骨架、设计 token、响应式规则都定下来了。Day 2 之后每天都是新开的 Claude Code 对话，看不到之前的聊天记录，只能通过读代码和这个 skill 来知道"已经有哪些规矩"。**新增或修改任何模块之前，先看这份文档，不要自己重新估一套颜色/间距。**

## 组件文件怎么组织

- 一个设计稿模块对应一个独立文件，放在 `src/components/` 下，文件名用能让人一眼对应上中文模块名的英文命名（例如"任务中心" → `TaskCenter.jsx`，"公告栏" → `AnnouncementBoard.jsx`）。
- 每个组件文件顶部集中放这个模块要用到的 mock 数据（文案、数字、列表内容），用中文注释标注每一块是什么，方便使用者自己定位到要改的地方去改文案或数字，不用去 JSX 里找。
- 代码可读性优先于精简度：能拆开写清楚就不要为了少写几行代码合并成难懂的写法。
- 今天这一阶段（骨架/静态还原阶段）如果模块本身涉及 tab 切换、展开收起这类交互，除非当天任务明确要求做成真交互，否则先只做"静态展示某一个选中状态"的视觉效果，不接 `useState`。图表也是先用占位色块代替，等真正做图表功能的那天再选库接入。

## 设计 Token（定义在 `src/index.css` 的 `@theme` 里）

不要在组件里直接写 `#00b85c`、`#191919` 这类十六进制颜色值或者自己另起一个颜色。这些 token 已经定义好，直接用对应的 Tailwind class 即可。如果设计稿截图上出现了下面表格里没有的新颜色，先问用户这个颜色的准确色值，不要自己估。

| Token | 值 | 用途 | 怎么用（class） |
|---|---|---|---|
| `--color-brand` | `#00b85c` | 品牌绿：顶部导航栏背景、主色按钮、角标底色 | `bg-brand` |
| `--color-brand-text` | `#01a65c` | 文字绿：链接文字、tab 选中态文字/下划线 | `text-brand-text` / `border-brand` |
| `--color-ink` | `#191919` | 一级文字：标题、重点内容（body 默认颜色，不用额外加 class 也是这个色） | `text-ink` |
| `--color-ink-secondary` | `#666666` | 二级文字：正文、列表项、表格内容 | `text-ink-secondary` |
| `--color-ink-tertiary` | `#949494` | 三级文字：日期、辅助提示、chevron 箭头这类小图标 | `text-ink-tertiary` |
| `--color-notice-text` | `#613700` | 黄色提示条（`bg-amber-50`）里的文字颜色 | `text-notice-text` |
| `--color-danger` | `#ff363f` | 数据卡片里表示"未达标"/异常的红色文字 | `text-danger` |
| `--font-sans` | PingFang SC 字体栈 | 全局正文字体，已经是 `body` 的默认字体 | 不用加 class |
| `--font-number` | SF Pro 字体栈 | 数字专用字体，只用在大数值上：百分比、统计数字、角标里的数字 | `font-number` |
| `--breakpoint-wide` | `1200px` | 自定义响应式断点，见下方"响应式规则" | `wide:` 前缀 |

## 已经定稿的尺寸规范

对照设计稿标注量出来的精确值，不要用 Tailwind 默认的 `rounded-lg`/`shadow-sm` 之类的近似值：

- **白色卡片圆角 20px**：每个模块最外层的 `<section>` 用 `rounded-[20px]`
- **灰色卡片/数据卡片圆角 12px**：比如任务中心里 4 个分类的灰色边框卡片、数据看板的指标卡片、流程导览的入口格子，用 `rounded-[12px]`
- **任务条圆角 4px**：任务中心里每一行小的待办条目，Tailwind 默认的 `rounded`（不加数值）刚好是 4px，直接用就行
- **卡片一律不加阴影**：不要用 `shadow-sm`、`shadow` 等 class
- **左侧导航栏宽度固定 200px**
- **右侧信息栏宽度固定 392px**：只在 `wide:`（≥1200px）时生效，小于 1200px 时不设固定宽度，让它撑满容器宽度
- **顶部导航栏高度 64px**：`h-16`
- **卡片之间、分栏之间的间距统一 16px**：`gap-4`
- **页面整体最小宽度 1024px**：`min-w-[1024px]`，低于这个宽度不再收缩，允许出现横向滚动条

字号规范：

| 用途 | 字号 | 字重 | class |
|---|---|---|---|
| 常规正文 | 14px | 400（默认） | `text-sm` |
| 顶部导航 logo、各模块 `<h2>` 标题、侧边栏分组标题 | 18px | 600 | `text-lg font-semibold` |
| 小标签/tag（比如公告栏的"通知""预警"） | 12px | 400 | `text-xs` |
| 日期 | 12px | 400 | `text-xs` |
| 数据卡片里"跟目标值对比"的辅助小字 | 10px | 400 | `text-[10px]` |

全项目字重只有两档：标题 600（`font-semibold`），正文 400（默认，不用加 class）。不要用 `font-medium`（500）这种中间档。

## 响应式规则

断点定义在 `--breakpoint-wide: 1200px`，用 `wide:` 前缀写响应式 class（不写前缀 = 默认样式，适用于所有宽度；加 `wide:` = 仅在 ≥1200px 生效）：

- **≥1200px**（`wide:`）：主内容区和右侧信息栏左右并排（`wide:flex-row`），右侧信息栏固定 392px 宽（`wide:w-[392px] wide:shrink-0`）
- **<1200px**（默认，不加前缀）：主内容区和右侧信息栏纵向堆叠（`flex-col`），右侧信息栏撑满宽度
- **最小宽度 1024px**：整个页面外层容器加 `min-w-[1024px]`，低于此宽度不再收缩，出现横向滚动条，不要另外写 JS 去判断窗口宽度

参考 `src/App.jsx` 里已经写好的例子。

## 协作规则（务必遵守）

- 颜色、间距、字号、圆角、布局比例这类跟设计稿有关的细节，只能来自参考截图或用户的明确确认。上面表格里列出来的都是已经确认过的，可以直接用；如果设计稿截图上出现了表格外的新数值（比如新模块要用一个新颜色、新的卡片宽度），不允许自己估一个数字，先问用户准确数值。
- 如果必须先估算再看效果调整（比如用户还没给精确设计稿、只能凭截图目测），要明确告诉用户这是估算值，写完之后用浏览器截图给用户对比原设计稿，等用户确认或纠正后再继续，不要估完就当作定稿往下做。
- 涉及会影响多个文件的架构选择（比如要不要新增一个设计 token、要不要改变组件拆分方式），先告诉用户，等确认后再动手。
