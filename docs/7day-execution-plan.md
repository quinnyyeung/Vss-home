# VSS首页 Vibe Coding —— 7天执行计划

每天开一个新的 Claude Code 对话时，把对应"Day N"整段复制粘贴过去作为开场白，
需要用到截图的地方，把截图一起发过去。每天结尾都有"验收标准"，你确认达标了，
再开下一天的对话。

## 通用规则（每天的开场白里都要带上，Claude Code不会记得前一天对话里的口头约定）

- 技术栈固定：React（纯JS，不用TypeScript）+ Vite + Tailwind CSS，图表用 Chart.js 或 ECharts（全项目统一）
- 这是延续之前的项目，代码在GitHub仓库里，今天的工作在已有代码基础上继续，不是从零开始
- 开始今天的工作前，先判断有没有能用得上或者该生成的 skill（现成可装的 skill，或者基于这个项目已经沉淀出来的约定生成一个项目专属 skill 都算），判断下来有的话先告诉我，评估一下用 skill 能不能提效，我确认后再用
- 除了mock数据的具体内容可以合理编写外，任何跟设计稿有关的细节（颜色/间距/字号/布局比例等）只能来自参考截图或我的确认，不允许自己估一个数值，拿不准直接问
- 把今天的工作拆成具体步骤，每完成一步就停下来，把结果给我看，等我确认没问题了再做下一步，不要一口气做完

## Day 1 —— 项目骨架 + 整体静态还原

目标：把项目从0搭起来，做出一个静态的、比例结构跟截图一致的骨架，先不做任何交互。

需要带的材料：首页参考截图（履约数据视图 + 采购订单数据视图）

步骤：

1. 用 Vite 初始化 React + Tailwind 项目；初始化 Git 仓库，结构适合后续推送 GitHub、用 Vercel 部署 —— 完成后给我看项目结构
2. 搭建整体页面骨架：顶部导航 / 左侧可展开收起的侧边栏 / 中间主内容区（任务中心+数据看板+评级汰换纵向排列）/ 右侧信息栏（公告栏+流程导览+培训中心+常见问题纵向排列）。布局容器必须用 flex/grid，不允许用绝对定位坐标写死位置 —— 完成后给我看效果，对照截图核对整体比例
3. 接入响应式：断点1200px（≥1200px三栏并排，<1200px右侧信息栏移到主内容区下方），最小宽度1024px（低于此宽度不再收缩，允许横向滚动）—— 完成后手动缩放窗口测试给我看效果
4. 推送到 GitHub，连接 Vercel 部署，确认线上链接能正常访问 —— 给我部署链接

验收标准：骨架结构、响应式框架、GitHub+Vercel部署链路都跑通，可以开始往里面填真实模块内容。

## Day 2 —— 数据看板模块（P0，核心交互+图表）

目标：数据看板这一块做出真实可用的tab切换和图表联动，这是整个demo证明能力的核心部分。

需要带的材料：数据看板区域的截图（履约数据tab + 采购订单数据tab两种状态）

步骤：

1. 还原"履约数据"tab的静态内容（5个指标卡片：到货满足率/到货准时率/拒收率/二配质检率/综合货损率，含达标/未达标状态样式，参考通用规则里判断出来能用的 skill）—— 完成后给我看
2. 还原"采购订单数据"tab的静态内容（多条折线趋势图）—— 完成后给我看
3. 实现两个tab之间的切换交互（`useState`）—— 完成后给我看切换效果
4. 补上图表的hover提示细节（对照截图里鼠标悬停显示的数据浮层）—— 完成后给我看

验收标准：两个tab能正常切换，图表数据和交互跟参考截图一致。

## Day 3 —— 评级汰换模块（P0，核心交互+图表）

目标：评级汰换这一块的tab切换、趋势图、预警列表全部做出真实交互。

需要带的材料：评级汰换区域的截图（评级结果tab + 汰换预警tab两种状态）

步骤：

1. 还原"评级结果"tab（多地区趋势折线图+hover提示+右侧结果表格，参考通用规则里判断出来能用的 skill）—— 完成后给我看
2. 还原"汰换预警"tab（预警卡片列表，含高危/中危标签+分页）—— 完成后给我看
3. 实现tab切换交互 —— 完成后给我看

验收标准：两个tab都还原到位，图表/列表/分页都能正常使用。

## Day 4 —— 任务中心 + 公告栏 + 侧边导航（P1）

目标：把首页里"点了有反馈"但不需要复杂逻辑的几块做完。

需要带的材料：首页整体截图（任务中心/公告栏/侧边导航部分）

步骤：

1. 还原任务中心的4个类目卡片（商品信息/履约单据/合同结算/价格管理），加上点击态反馈 —— 完成后给我看
2. 还原公告栏的5个tab切换（最新/预警/通知/规则/函件）—— 完成后给我看
3. 实现侧边导航栏的分组展开/收起交互 —— 完成后给我看

验收标准：这三块都还原且可以正常点击交互。

## Day 5 —— 流程导览跳转 + 极端值处理 + 响应式收尾（P1）

目标：补齐剩下的P1交互，并且把前几天做的模块过一遍响应式和边界情况。

需要带的材料：流程导览页面的参考截图

步骤：

1. 实现首页"流程导览"入口点击后跳转到一个静态图展示页（不需要做成真实可交互的流程图，用参考截图直接展示）—— 完成后给我看跳转效果
2. 补上2-3处极端值处理：长文本（供应商名称/公告标题）超长时截断、指标数值0%或100%时卡片不破版、公告栏/常见问题为空时的空状态提示 —— 完成后给我看
3. 把Day1-4做完的所有模块在1200px断点前后都过一遍，检查响应式表现是否一致、有没有遗漏的模块没跟上断点规则 —— 完成后给我看检查结果

验收标准：流程导览可跳转、极端值不破版、所有已完成模块的响应式表现一致。

## Day 6 —— 智能助手面板 + P2收尾 + 部署检查

目标：把静态展示类的内容收尾，整体过一遍质量，确认最终可演示状态。

需要带的材料：商家智能助手悬浮面板截图

步骤：

1. 做一个简化的智能助手悬浮按钮+静态面板（点开显示欢迎语+几个FAQ按钮即可，不接入真实问答逻辑）—— 完成后给我看
2. 把P2部分（顶部导航/店铺选择器/培训中心/商家信息静态卡片）核对一遍，确保内容跟截图一致 —— 完成后给我看
3. 全站走查一遍——重点看还原度、响应式、极端值这三块有没有遗漏或者跟截图对不上的地方，修复发现的问题 —— 完成后给我看修复清单
4. 确认GitHub最新代码已经推送、Vercel部署的最终版本可以正常访问 —— 给我最终链接

验收标准：整个demo功能完整、可以完整点击演示一遍，线上链接正常访问。

## Day 7 —— 打磨 + 面试叙事准备（缓冲日）

目标：这一天不追加新功能，专门用来查漏补缺和准备怎么讲这个demo。

步骤：

1. 通读一遍全部代码，把自己看不太懂的地方记下来，问Claude Code讲清楚（或者拿回来问我）—— 整理成一份"我需要弄懂的点"清单
2. 找一找还有没有余量可以精修的细节（视觉对齐、交互流畅度），逐个修 —— 完成后给我看改动
3. 结合这个demo，梳理一遍"设计稿 → AI辅助转代码 → 前端验证提效"这条口头叙事逻辑草稿，准备面试的时候能讲清楚
4. 剩余时间作为缓冲，处理前六天遗留的小问题

验收标准：demo运行稳定、能完整演示，你自己能讲清楚这个demo是怎么做出来的、背后的取舍是什么。
